# คู่มือผู้ใช้ Camfrog

English version: `USER-MANUAL-EN.md`.

exe แปดตัว หนึ่งคู่มือ

แอป: `room-control`, `chat-im-private`, `status-changer`, `status-random`, `status-marquee`, `im-autoreply`, `music-dj`, `web-status` ทุกแอปใช้ได้เฉพาะ Windows และต้องเปิด Camfrog ไว้ ยกเว้น `web-status` ที่ทำงานผ่านเว็บไซต์

**อัปเดต** ทุกแอปตรวจ GitHub release ตอนเปิด (ขึ้น banner เฉพาะเมื่อมีเวอร์ชันใหม่) และมีปุ่ม **Check for updates** ส่วน CLI ใช้คำสั่ง `<app> update` การอัปเดตดาวน์โหลดเฉพาะไฟล์ของแอปนั้น ตรวจกับ `SHA256SUMS.txt` ของ release แล้วติดตั้งตอนปิดแอป (`<app>.new` กับ `camfrog-update.cmd` เป็นตัวสลับไฟล์) ไม่ต้องมีบัญชีหรือโทเคน และไม่ส่งข้อมูลอะไรขึ้น GitHub เลย เผยแพร่ release ด้วย `python tools/release.py`

## 1. ติดตั้ง

1. ติดตั้ง CPython 3.12 รุ่นปกติ แบบ 64-bit
2. รัน `doctor.bat` ก่อน เพื่อตรวจ Python และทดสอบการโหลด `pywin32`
3. ดับเบิลคลิก `build.bat` (หรือ `full-build.bat` สำหรับทุกแอปรวมแอป LINE) ไฟล์ exe จะอยู่ใน `dist\<app>\`
4. ถ้า build ขึ้น `pywin32 ... no matching distribution` ให้ติดตั้ง CPython 3.12 แบบ 64-bit ลบ `.venv` แล้วรันใหม่

## 2. เริ่มใช้ครั้งแรก

1. เปิด Camfrog แล้วเข้าห้อง (อย่าย่อลง tray)
2. เปิดแอปแล้วกด **Setup → Auto-detect** (แอป room/im) หรือ **Discover controls** (แอป status/private-chat/web) เพื่อให้โปรแกรมหา control ให้อัตโนมัติ
3. เปิด `dry_run` ไว้ก่อนเสมอขณะทดสอบ โหมดนี้แค่บันทึกว่าจะส่งอะไร ไม่ส่งจริง
4. เปิดโหมดจริงเมื่อพร้อมแล้วเท่านั้น: ช่อง **LIVE** / **Send statuses live to Camfrog** / **Send live**

## 3. ควบคุมห้อง

- ตั้งนิคของตัวเอง (`My nickname`) จำเป็นสำหรับโหมดจริง
- **Window title regex** ใช้เลือกว่าจะควบคุมหน้าต่าง Camfrog ใด
- กฎตอบอัตโนมัติ: รูปแบบ regex, ข้อความตอบ, คูลดาวน์รายคน, ตอบเฉพาะเมื่อถูกเรียกชื่อ, ภาษา (`th`/`en`) ทดสอบด้วย **Test rule** ก่อนเปิดจริง
- **Save & Start** เริ่มบอทเบื้องหลัง **Stop** หยุด ปิดหน้าต่างไม่ทำให้บอทหยุด
- กันสแปม: ไม่ตอบข้อความที่มีลิงก์ (ค่าเริ่มต้น `ignore_links`) และข้ามตาม `skip_patterns`

## 4. ตอบแชทส่วนตัว

- แอปแยก config แยกกฎ การตอบในห้องไม่ยุ่งกับแชทส่วนตัว
- **ต้องระบุรายชื่อเพื่อน** (`only_nicknames`) ตอบเฉพาะคนที่อยู่ในรายชื่อ
- เพดานเข้มกว่าปกติ (ค่าเริ่มต้น: ตอบเพื่อนคนละ 1 ครั้งต่อชั่วโมง วันละ 3 ครั้ง รวมชั่วโมงละ 10 ครั้ง) ทุกคำตอบขึ้นต้นด้วย `[auto] ` และจะไม่ตอบบรรทัดที่มีคำนำหน้านี้
- หน้าต่างที่เปิดอยู่ก่อนบอทเริ่มจะไม่ถูกตอบ
- หลังตอบโหมดจริง IM Auto-reply จะหา echo ของข้อความขาออกในประวัติแชตฝั่งเครื่อง แล้วเลื่อนไปยังบรรทัดนั้น นี่เป็นหลักฐานจาก UI ในเครื่องเท่านั้น Camfrog ไม่มีการตอบรับยืนยันว่าผู้รับเห็นข้อความ ถ้าส่งไม่สำเร็จก่อนกดส่ง ระบบจะเก็บข้อความไว้ลองรอบถัดไป แต่ถ้าผลกำกวมจะไม่ส่งซ้ำเพื่อป้องกันข้อความซ้ำ ตั้ง `safety.restore_previous_window` เป็น `false` หากต้องการให้หน้าต่างแชต Camfrog ค้างอยู่ด้านหน้า
- แท็บ **Activity Log** แสดง log ของแอปตามไฟล์ที่ตั้งไว้ บันทึกการเปิด/ปิดแอป การบันทึก/โหลด config ผล Start/Stop และ helper วงจรชีวิต worker การกรอง IM กฎที่ไม่ตรง ตัวอย่างตอบกลับ การตอบ และ error พร้อมรายละเอียดที่มีอยู่ หน้าจอจะอัปเดตขณะเปิด GUI ตัวเลือก **Log chat text** ใน Advanced กำหนดว่าจะบันทึกเนื้อหาข้อความด้วยหรือไม่ ให้ปิดเพื่อไม่เก็บข้อความแชตใน log แต่ละแอปใช้ไฟล์ log และ worker ของตัวเอง
- โฟลเดอร์ข้อมูลของแอปนี้รัน worker ได้ครั้งละหนึ่งตัว Activity Log จะแสดงเมื่อไม่มีกฎตอบที่ตรงหรือมีการกรองข้อความ

## 5. จัดการหน้าต่างแชทส่วนตัว

- แสดงรายชื่อหน้าต่างแชทส่วนตัวที่เปิดอยู่ **Refresh** โหลดใหม่ ดับเบิลคลิกหรือ **Activate selected** เพื่อโฟกัส ไม่มีการอ่านหรือส่งข้อความ
- ตัวกรองชื่อหน้าต่าง (regex) กับจำนวนสูงสุดช่วยจำกัดรายชื่อ **Save filters** บันทึกลง config ของแอปนี้
- **Discover controls** ดึงรายการ control ลง `controls.txt` เพื่อตั้ง selector

## 6. Status Changer: Random, Marquee และ Activity Log

- `status-changer.exe` แยก Random และ Marquee เป็นคนละแท็บและแยก pool สิบช่อง หากพบฐานข้อมูล pool จากโฟลเดอร์เดิมจะนำมาใช้ exe `status-random.exe` และ `status-marquee.exe` รุ่นเดิมยังอยู่เพื่อรองรับการใช้งานเดิม
- **Random:** สุ่มข้อความจากสิบช่อง **Switch every** ตั้งช่วงวินาทีขั้นต่ำ 0.3 วินาที
- **Marquee:** **Step** ตั้งวินาทีต่อเฟรม และเป็นช่วงหน่วงก่อนเปลี่ยนช่องเมื่อปิด Scroll (ขั้นต่ำ 0.3), **Stride** ตั้งจำนวนกลุ่มตัวอักษรต่อเฟรม และ **Scroll** เปิดหรือปิดการเลื่อน Marquee จะใช้ช่องที่มีข้อความเรียงตามลำดับ และ History จะไม่สลับลำดับช่อง เมื่อเปิด Scroll แต่ละช่องจะเลื่อนจนจบก่อนเริ่มช่องถัดไป **Loop slots** จะเริ่มช่อง 1 ใหม่หลังช่องสุดท้าย หากปิดไว้จะหยุดหลังช่องสุดท้าย ระบบไม่แยกสระหรือวรรณยุกต์ไทยออกจากพยัญชนะ ค่า **Switch every** ใช้กับ Random เท่านั้น
- **Start** เริ่มโหมดที่เลือกทันที เปิด worker ได้ครั้งละโหมดเดียว หน้าต่างแสดงว่าโหมดใดกำลังทำงาน **Stop** หยุด worker
- **Activity Log** รวมเหตุการณ์จาก GUI กับ log ของ worker ทั้งสองโหมด รายการ GUI ไม่เก็บข้อความสถานะ แต่ log ของ worker อาจมีข้อความสถานะที่ส่งไป Camfrog กด **Open log folder** เพื่อเปิดโฟลเดอร์ไฟล์ log

## 7. ประวัติ ตารางเวลา ภาษา

- ทุก status ที่ตั้งถูกเก็บลงประวัติ ใน Random mode ถ้าเปิด `use_as_source` จะเลือกข้อความถัดไปจากประวัตินั้น (`rotate`/`random`/`most_used`)
- ตั้ง pool ต่างกันตามช่วงเวลาของวัน (`status.schedules`) ระบุ `start`/`end` เป็น `HH:MM`
- `status.language_cycle: ["th","en"]` สลับไทย/อังกฤษทุกครั้งที่เปลี่ยน status รายการสถานะเป็นคู่ `{th, en}` ได้
- `"language": "auto"` ตามภาษาหน้าจอ Windows อัตโนมัติ

## 8. ดีเจเพลง

- บอทห้องที่เล่นเพลงได้พร้อมรับคำขอจากแชท ต้องเปิด Camfrog และเปิด `autoreply` (ดีเจใช้ระบบอ่านแชทนี้) แล้วตั้ง `dj.enabled`
- คำสั่งในแชท ค่าเริ่มต้นนำหน้าด้วย `!`: `!request <เพลง>` (หรือ `!req`, `!song`), `!queue`, `!current` (หรือ `!np`), `!skip`, `!help` หน้าต่างคิวในแอปแสดงสถานะเดียวกับไฟล์ โดยมีปุ่มเจ้าของบอทคือ **ข้ามเพลงปัจจุบัน** / **ล้างคิว**
- คำขอแรกเล่นทันที เพลงถัดไปเข้าคิว (จำกัดต่อคนตาม `max_per_user` เพลงซ้ำหรือเพลงที่กำลังเล่นจะถูกปฏิเสธ) คำสั่ง `!skip` ใช้ได้กับผู้ขอหรือเจ้าของบอท
- โฟลเดอร์เพลง: กด **Browse** เพื่อเลือกโฟลเดอร์ แล้ว `!request` จะจับคู่ชื่อไฟล์เสียงที่รองรับ (ตรงบางส่วนของชื่อและไม่สนตัวพิมพ์เล็กใหญ่) แอปค้นหานามสกุลเสียงทั่วไป เช่น WAV, MP3, WMA, AAC/M4A, AIFF/AU, FLAC, OGG/Opus และ MIDI
- **Audio backend** `chat` (ค่าเริ่มต้น) จะประกาศในแชทอย่างเดียว ส่วน `local` จะเล่นไฟล์ที่ Windows MCI เปิดได้บนเครื่องนี้ และเริ่มเพลงถัดไปเมื่อเพลงจบ การรองรับขึ้นอยู่กับการแมปนามสกุลไฟล์ใน Windows MCI และ codec ที่ติดตั้ง เพื่อให้ห้องได้ยิน ต้องส่งเสียงของเครื่องนี้เข้า input ของ Camfrog ด้วย virtual cable หรือ "Stereo Mix"
- เริ่มแบบ dry-run ก่อน: บอทจะแค่บันอกว่าจะประกาศอะไร คำขอเพลงยังเข้าคิว แต่ไม่พิมพ์อะไรเข้าห้อง

## 9. สถานะผ่านเว็บ (รุ่นทดลอง)

สถานะ: รู้ขั้นตอน login แล้ว และดึง endpoint อัปเดตสถานะได้จากหน้า home.php ที่ล็อกอินอยู่ (POST `{status, csrf}` ไป `/ajax/update_status.php`) แต่ยังกั้นไว้ CLI ที่ส่งจริงต้องใส่ `--confirm-update`; ปุ่ม Start ใน GUI จะแสดงคำถามยืนยันก่อนส่ง

- ไม่ใส่ argument เปิด GUI ใส่ argument ใช้ CLI (`web-status.exe --login Seaza --status "..."`) ค่าเริ่มต้นคือ dry-run ไม่มีการต่อเน็ต
- Web Status เปิดเป็นภาษาไทย คลิก **TH / EN** ด้านบนเพื่อสลับป้ายกำกับหน้าจอ ข้อความแจ้งสถานะทั่วไป คำยืนยันการส่งจริง และชื่อเหตุการณ์ใน Activity Log เป็นภาษาอังกฤษหรือกลับมาเป็นภาษาไทย รายละเอียด error เชิงเทคนิคยังเป็นภาษาอังกฤษ รายการ log ใหม่จะใช้ภาษาที่เลือก ส่วนรายการเดิมจะเปลี่ยนภาษาเฉพาะตอนแสดงใน GUI
- ในแท็บ Setup กรอกสถานะได้สูงสุด 10 บรรทัดในช่องหมายเลขแยกกัน ปุ่ม **Save to webtext.db** บันทึกแต่ละช่องไว้ข้างแอป และ **Start** จะบันทึกค่าปัจจุบันก่อนวนเปลี่ยนเฉพาะช่องที่ไม่ว่าง ค่าเริ่มต้น **Switch every** คือ 10 วินาที โหมด Live บังคับช่วงต่ำสุด 10 วินาที ส่วน dry-run ยังใช้ค่าที่ต่ำกว่าได้ **Timeout** เริ่มต้นที่ 15 วินาที ตั้งได้ 2–120 วินาทีและปรับตามเครือข่ายได้
- ช่องกรอกใน GUI รองรับ **Ctrl+A** (เลือกทั้งหมด), **Ctrl+C** (คัดลอก), **Ctrl+V** (วาง) และ **Shift+Insert**; หากจำเป็น คลิกขวาที่ช่องแก้ไขแล้วเลือก **Paste**
- Web Status ส่งข้อความเต็มของแต่ละช่อง และไม่มีโหมด Marquee หรือการเลื่อนทีละเฟรม **Loop rounds** กำหนดจำนวนรอบครบทุกช่อง: `0` วนไม่จำกัด และ `1` หยุดเมื่อครบหนึ่งรอบ
- แท็บ **Activity Log** แสดงและบันทึกเหตุการณ์ลง `web_status.log` ข้างแอป รายการเริ่มหมุน รายการลองใหม่ และรายการอัปเดต Live ที่ล้มเหลวจะบันทึกโหมด ช่วงเวลาที่ตั้งและช่วงเวลาที่ใช้จริง จำนวนรอบ timeout และจำนวนช่องที่มีข้อความ การรับ rate limit จะทำตาม `Retry-After` ของ server ทั้งแบบจำนวนวินาทีหรือ HTTP-date; ถ้าต้องรอเกิน 24 ชั่วโมงจะหยุดอัตโนมัติแทนการลองก่อนเวลา หาก server ไม่ระบุเวลารอ จะลองใหม่แบบ 30/60/120 วินาที สูงสุด 5 ครั้ง ส่วน error ชั่วคราวขณะอ่านหน้า profile ก็ลองได้สูงสุด 5 ครั้งตาม backoff หาก POST timeout จะไม่ลองซ้ำอัตโนมัติ เพราะ server อาจบันทึกสถานะไปแล้ว กด **Stop** เพื่อยกเลิกการลองใหม่และป้องกันไม่ให้ GET หน้า profile ส่งต่อไปยัง POST สถานะ หาก POST เริ่มส่งไปแล้ว คำขออาจเสร็จสิ้นได้ แต่จะไม่มีการกำหนดอัปเดตครั้งต่อไป รายละเอียด log จะกรองข้อความสถานะ รหัสผ่าน cookie ค่า CSRF และ header ที่มีข้อมูลลับออก
- ในแท็บ **Account & Session** กด **Open login page** แล้วลงชื่อเข้าใช้ในเบราว์เซอร์ตามปกติ จากนั้นคัดลอก `PHPSESSID=...` จาก request ของ `profiles.camfrog.com/home.php` ใน DevTools แล้ววางในช่อง session กด **Login** เพื่อตรวจสอบ cookie ปัจจุบัน หากยืนยันว่าลงชื่อเข้าใช้แล้ว ระบบจะพร้อมทำงาน ค่า cookie อยู่ในหน่วยความจำเท่านั้น
- เมื่อเลือก **Send live**, ปุ่ม **Start** จะตรวจ cookie ปัจจุบันหากยังไม่ได้กด Login เพื่อยืนยัน session จากนั้นถามยืนยันและเริ่มวนสถานะ ปุ่ม **Stop** หยุดการวนและยกเลิก session ที่ยืนยันไว้ ดังนั้น Start ครั้งถัดไปจะตรวจสอบใหม่ ค่าเริ่มต้นยังเป็น dry-run
- การล็อกอินด้วยรหัสผ่านผ่าน CLI อาจติด CAPTCHA และโปรแกรมจะไม่ข้าม CAPTCHA สำหรับ CLI, `--probe` ตรวจ session แบบอ่านอย่างเดียว และ `--cookies-file` รับไฟล์ cookie รูปแบบ Netscape ห้ามวางรหัสผ่านหรือ cookie ในแชท issue หรือไฟล์

## 11. เบื้องหลัง log ไฟล์

- Room/IM: ปุ่ม GUI **Save & Start** / **Stop** หรือคำสั่ง CLI `start` / `state` / `stop` (แบบซ่อน ไม่มีหน้าต่าง) สถานะ: ปุ่ม **Start**/**Stop** ของตัวเองกับ worker ที่มากับแอป
- แต่ละแอปบันทึก log ข้าง config ตัวเอง (source CLI ใช้ `camfrog_auto.log`) แก้ `config.json` ตอนรันได้ ค่าถูกต้องมีผลใน ~3 วินาที ค่าผิดถูกปฏิเสธและ log ไว้
- ทุกครั้งที่ส่งจะดึง Camfrog ขึ้นมาชั่วครู่ กด Enter แล้วคืนโฟกัสเดิม Camfrog ต้องเปิดอยู่ (ย่อไว้ได้เฉพาะเมื่อ control ยังเข้าถึงได้ — ตรวจด้วย Discover)

| อาการ | วิธีแก้ |
|---|---|

## 13. ความปลอดภัย

- `dry_run` เปิดเป็นค่าเริ่มต้น คำตอบถูกจำกัดความถี่ (คูลดาวน์รายคน ช่องว่างรวม เพดานรายชั่วโมง)
- บรรทัดที่ไม่ใช่รูป `ชื่อ: ข้อความ` ถูกข้าม คำตอบที่ขึ้นต้นด้วย `/` ถูกบล็อก ไม่มีการเตะอัตโนมัติ
- ห้าม commit รหัสผ่าน cookie token หรือข้อมูลส่วนตัว ไฟล์ cookie อยู่นอก repo เสมอ
- ตรวจเงื่อนไข Camfrog และกฎห้องก่อนเปิดระบบอัตโนมัติ แจ้งช่องโหว่แบบส่วนตัวตาม `SECURITY.md`
