## 3. BACKGROUND EXECUTION ARCHITECTURE

Review and refactor the background runtime to support reliable operation.

Identify the most appropriate architecture based on the existing codebase.

Potential components:

```text

    |
    +-- Application Lifecycle Manager

    |     |

    |
    +-- GUI / System Tray Controller
    |

    |
    +-- Health & Diagnostics
    |
    +-- Structured Logging
```

Treat this as a conceptual architecture, not an instruction to create unnecessary modules.

Reuse existing components where practical.

### Required Behaviors

1. Background operations must not depend on a visible GUI window unless the platform requires it.
2. Background workers must not block the GUI event loop.
3. Long-running operations must support cancellation and graceful shutdown.
4. Unexpected worker termination must be detected and logged.
5. Recoverable failures must use bounded retries with exponential backoff and jitter.
6. Reconnection must restore valid application state.
7. Startup must not create duplicate worker instances.
8. Shutdown must stop workers and release resources.
9. Background execution must not silently lose tasks.
10. Errors must remain observable even when audible and desktop notifications are disabled.

Implement single-instance protection if the existing application requires it.

Avoid unlimited retries, busy loops, orphan processes, and uncontrolled thread creation.

```text

INFO

```

### Background Error Policy

**DEBUG / INFO**
- Record diagnostics when configured.
- No audible notification.
- No desktop notification.

**WARNING**
- Record structured logs.
- Apply safe recovery logic.
- No audible notification.
- No unnecessary modal dialog.

**ERROR**
- Record details and relevant context.
- Trigger appropriate recovery behavior.
- Update application health status.
- Do not generate audible alerts.

**CRITICAL**
- Record durable failure evidence.
- Stop unsafe operations when necessary.
- Update health status.
- Preserve an explicit, accessible error indication.
- Never silently ignore the failure.
- Do not generate application-controlled notification sounds.

Do not expose tokens, passwords, session cookies, private chat contents, or other sensitive values in logs.

Silent operation must not mean invisible failure.
